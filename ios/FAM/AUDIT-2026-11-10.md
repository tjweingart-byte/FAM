## Gaps, ranked

1. **Terms re-acceptance never asked** (#122). Fix: read `terms` from `/api/v1/consent` after sign-in/launch and show the web's non-dismissable card ("We've updated our Terms" / "One thing before you go on", the box, Continue), POST `{scope:"terms", allow:true, version}`.
2. **Retired / deprecated client not handled** (#136, #137). Fix: in `FAMAPI.check`, on 426 or `X-FAM-Client-Status: retired` raise an app-wide "update FAM" screen with the server's `error` and `update_url`; on `deprecated` say once "A newer version of FAM is available" with the store link.

## Gaps, ranked

1. **No loading-screen give-up (§497), and none of its sentences.** Web: 45 s of server silence, re-armed by each /api/progress step, then `voice_wait` + 15 s once the script is with the voice; it fails with "That is taking longer than expected. Is the server running?" or "The voice is taking longer than expected to start. Try again in a moment." iOS uses URLSession's 60 s idle timeout and 3 reconnects, so a dead server holds the screen for about 4 minutes before "Could not generate that briefing". A cold voice can also trip the 60 s timeout mid-wait. Fix: add a deadline to LoadingModel, re-armed by poll answers and `voice_wait`, using these sentences, and give the audio request a timeout longer than the voice's.
2. **Terms re-acceptance is missing (checkTerms / acceptTerms, §228).** An account that never agreed, or agreed to an older version, is never asked on iOS. Fix: read `terms` from /api/consent after sign-in and at launch. When `!accepted`, show the blocking card ("We've updated our Terms" / "One thing before you go on", the tick box, Continue) and POST scope "terms".
3. **The limit card has no "See plans".** Fix: add the primary "See plans" button that closes the card and opens PlansSheet.
4. **The sample-script / rejected-key note is missing (`genStatusNote`).** Staging, demo or a rejected key never says so under the steps, dial or glide. Fix: read /api/health once (mode, environment.zero_spend, credentials.state) and put the web's line in place of the status text.

7. **The toast sits at a fixed 96 pt** instead of just above the mini player when it is up, else the tabs (placeAboveBars). Fix: lift it by the mini player's height when `miniShown`.
8. **Rail and tile pictures do not blur up** when they land after the tile was drawn (`.seed-img`, BLUR_UP, 320 ms). Fix: the same `Arrival` blur used on the player, inside `Picture`.
9. **No queue flight (Motion.toQueue).** Only the end bump and badge are drawn. Fix: a matchedGeometry or overlay ghost, 28x22 to 12x10, 450 ms arc.

## Gaps, ranked (MISSING / DIFFERS only)

1. **No /api/client-status at launch, no 426 update screen, no `deprecated` handling** (H8, H9, client-status). IOS_APP.md says it cannot be added after 1.0 ships. Fix: call `/api/v1/client-status` at launch and in `check()` turn 426 into an update screen with `update_url`; read `X-FAM-Client-Status` once for a nudge.
2. **No iOS release in `releases/registry.json` and no iOS contract** (H21, H22). Fix: `tools/cut_release.py --platform ios` per submission; make `test_ios_app_contract` scan every Swift file.
3. **Session cookie overrides the Keychain bearer** (H3, logout). Fix: give FAMAPI and the player a session with `httpShouldSetCookies=false` / `httpCookieStorage=nil`, or clear `HTTPCookieStorage` on sign-out/delete.
4. **Joint-mix invites cannot be joined** (`/api/mixes/join` never called, `/j/` unhandled, AASA lacks `/j/*`). Fix: handle the link (and a paste fallback), call `joinMix`, the web's sheet and toast; add `/j/*` to the AASA.
5. **Universal links not built** (`/s/`, `/m/`, AASA entitlement). Fix: associated-domains entitlement + `onOpenURL`/`onContinueUserActivity` routing to the shared episode / mix.
6. **Terms re-acceptance never asked** (GET/POST /api/consent `terms`). Fix: decode `terms`, show "We’ve updated our Terms" / "One thing before you go on" sheet, POST `scope:"terms"`.
7. **Audio is PCM only, no Opus, no R2 links** (/api/audio, H14). ~15x the bytes per episode and every replay through the server. Fix: decode fam-opus (AVAudioConverter/libopus), send `fmt=opus&link=1`, fall back with `link_failed=1`.
8. **No push for a mix's listen time** (/api/push/subscribe). Fix: APNs on the server and a device-token subscribe route; until then the row says so.
9. **No /api/health**: no Staging/Zero-spend ribbon, no demo-mode / KEY REJECTED note under the loading steps. Fix: ask at launch, draw the ribbon and `genStatusNote`.
10. **No /api/voice/wake on returning to the foreground**. Fix: on scenePhase `.active` (signed in), POST `/api/v1/voice/wake`.
11. **Waiting screen far thinner than the status page** (/waitlist/me, /api/waitlist/me, /people, /add): no place in line, batch, invites, referral link, friend search/add, profile edit. Fix: decode the rest of `/api/waitlist/me` and build those rows.
12. **`waitlisted` status locks iOS out even with the waitlist off** (/api/auth/me). Fix: decode `waitlist` and wait only when `waitlist && status=="waitlisted"`.
13. **Any `X-FAM-Waitlist` refusal shows the waiting screen** (H4). Fix: only `/waitlist/me` → waiting; `/waitlist` → signed out.
14. **API base hard-coded to production** (H23). Fix: build setting, staging for TestFlight.
15. **Password change re-signs in silently** vs web's "Password changed — other devices signed out" (/api/auth/password). Fix: decide one behaviour; at least show the web's toast.
16. History/progress/save fields not cut to server limits (POST /api/history): over-long → 422, row silently lost. Fix: `prefix(500/200/300/80)` as the web.
17. Referral code not sent on an iOS sign-up while the waitlist runs (/api/waitlist/join). Fix: carry `referral_code` from a referral link into signup.
18. My Vibe asks `limit=200` vs the web's 40 (/api/vibes). Fix: align (owner's call).
